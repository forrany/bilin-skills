# 比邻留学 · 活动列表评估

审核**已存在**的美本申请活动列表，判断它撑不撑得起学生的申请定位。

核心比喻：活动列表 = 简历，**Major = 岗位**，**学校（尤其 ED 校）= 公司**，PS = 个人故事，补充文书 = Why this company。**没有岗位，简历无从评估。**

## 何时用 / 何时不用

**用**：已有活动列表，要打分、排序、提修改建议、查匹配度、查真实性。

**不用**（归 `bilin-admissions-consultant`）：从零规划活动、选校、定专业。也不写文书——本 skill 只**读**文书做一致性校验。公众号文章归 `bilin-wechat-essay-write`。

## 输入门槛（硬闸）

开工前必须拿到。**缺任一项就停下来发 [`references/INTAKE.md`](references/INTAKE.md) 清单，不要硬推**。

1. **申请 Major**（必填）
2. **目标校 / ED 校**（必填）—— 取舍与排序要跟着 ED 校改
3. **活动列表原文** —— 每条含 `title` / `description` / `position` / `time`
4. **主文书 + 补充文书**（optional）—— 有则查一致性，无则标 `N/A`

## 工作流

1. **收件校验** → 缺必填就停，发清单。
2. **检索学校偏好** → WebSearch 查 `[校名]+[major]` 的 `what we look for` / 官方 criteria。**必须检索，不许脑补**；查不到标"待核实"。
3. **三层匹配评分** → 读 [`references/SCORING.md`](references/SCORING.md)，打整体 + 专业 + 学校 + 文书，各 0-6。
4. **逐字段审核 + 标风险** → 读 [`references/FIELD-CHECKLIST.md`](references/FIELD-CHECKLIST.md) 逐条过四字段；读 [`references/REDMARK.md`](references/REDMARK.md) 定级并**算出独立活动占比**。
5. **出报告** → 按 [`references/REPORT-TEMPLATE.md`](references/REPORT-TEMPLATE.md) 写 7 节。

## 输出契约

7 节报告：一页概览 → 主题与定位 → 三大匹配详解 → Red mark 清单 → 排序建议 → 逐条修改建议 → 综合判断。

四个 0-6 分：**整体 / 专业匹配 / 学校匹配 / 文书一致性**。Red mark 三级：**黄（注意）→ 橙（必改）→ 红（重做）**。

**0-6 是改进指引用的诊断分**，不对应、不预测任何学校的内部 reader 评分——各校量表不同（有的 1-7、有的 1-9），不要拿去逼近或换算。判据来自 Common App 活动列表的跨校通用标准，见 `SCORING.md` 开篇。

Common App 系统级约束（10 条上限、字符数）**不用管**，系统自己会拦。

## 五条铁律

1. **无专业、无学校 → 不开工。**
2. **学校匹配度必须检索，不许脑补**；查不到标"待核实"。
3. **分数必须配顾问式段落**——比邻禁止冷冰冰的多维评分表，每个分数后面跟一段人话。
4. **真实性存疑必打 red mark，独立活动占比必算。**
5. **不替家长做决定，但必须说清位次**：现在什么水平 + 三大风险 + 如果只改三件事该改哪三件。
