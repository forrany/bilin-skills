本 skill 第一次在**真实学生案例**上使用暴露出三组问题，本文件是 v1.1 → v1.2 的直接依据。

**学生信息已脱敏**：不出现姓名、校名、具体作品名。场录用「S 同学」代指；活动用类型描述（原创歌曲 / 录音制作课 / 表演考级 / 校队）。

## 一、发生了什么

顾问用本 skill 评估 S 同学（ED 候选 2 所、专业候选 Music + Philosophy）的活动列表。第一轮报告出了三组问题：

### 问题 1：5 处编撰（材料里不存在的内容）

| # | 编撰模式 | 具体形态 |
|---|---|---|
| 1 | 头衔升级 | 活动写 `Producer`，但作品集文件署名是 `Produced by:` 另一个人 |
| 2 | 跨条移植 | 把「40 轨 Logic Pro」挂在原创歌曲名下；那 40 轨实际出自活动信息表里九年级录音制作课的结课作业 |
| 3 | 术语加料 | 原文只写 `final dialogue`，报告写成 `Socratic dialogue` |
| 4 | 空白填充 | 表演考级项目的训练内容，材料里零记录，报告编出了具体内容 |
| 5 | 年限拉长 | 写 `Four-year setter`，但材料显示九年级在 JV（青年队） |

其中 #1 和 #2 如果照抄进 Common App，招生官一追问就穿。

### 问题 2：ED 选项和专业选项没有

S 同学在两个 ED 候选校之间犹豫，专业也是 Music / Philosophy 双候选。报告只按一个组合出结论，顾问被迫追了一句「ED 选项和专业选项没有」。

### 问题 3：没有改前改后评级

顾问要回答家长「照你说的改，能到什么程度」，但报告只有现状分，没有改后预期。

### 问题 4：外教需要一份精简交付

顾问要转发给外教（native-speaker coach），需要的是「分专业的活动排序建议 + 按重要性分级的修改建议，英文、简洁」，而不是整份中文报告。

## 二、根因分析

**问题 1 的根因不是"模型不听话"，是结构诱导。** 原有 skill 给改写作案定了两条规范，一条要求「强动词 + 量化结果 + 第三方背书」，一条要求「给出可直接粘贴的英文替换文案」——而 S 同学的原始列表恰恰**缺数字、缺头衔支撑、缺成果**。模型为了让文案"达标"，就替学生把缺的东西补上了。三条技术性禁令（不编录取率/政策/门槛）覆盖不到"改写作案里的数字与头衔"这一层。

**关键技术盲区**：编出来的内容比原文更漂亮、更专业、更符合"好列表该有的样子"，所以最难的部位是**自查**——它读起来对。

**问题 2 的根因**：底层比喻（Major = 岗位，ED 校 = 公司）没有落实到"同一份简历投两家公司的两个岗位时，必须分组合出结论"。

**问题 3、4 的根因**：产品需求里"轻量模式"被 v1.0 列为「不添加」，但它以另一种形态（外教版 + 改后预期分）真实出现了。

| 问题 | 修复 | 落点 |

| 编撰 | 七类出处标签 + 五种编撰模式自查 + `{{占位符}}` 纪律 + 出处对账表 | `EVIDENCE.md`、`FIELD-CHECKLIST.md`、`REDMARK.md` 开篇依据天花板 |

## 四、尚未解决的问题（诚实记录）

1. **防编撰有效性未在第二份真实案例验证。** 本文件的防线设计有理有据，但"第一次真实失败 → 设计防线 → 第二次验证"的闭环还没走完。
2. **出处对账的边际成本未知。** 逐条三列对账 + 五种模式自查会增加单份报告的工作量，是否导致顾问觉得"太重"，待验证。
3. **外教版能否真的减少外教阅读量，未实测。** 只凭顾问的一句话需求设计，未让一位外教实际读过。
4. **矩阵化在 ED 未定时的灵活性未定。** 本次案例 ED 有明确候选；若顾问给的是「帮我看看我这两所 ED 选哪个」这种开放选校诉求，本 skill 的边界仍需澄清——选校本身归 `bilin-admissions-consultant`，本 skill 只做"给定候选后的对比"。
