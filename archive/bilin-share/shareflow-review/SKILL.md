# Shareflow Review

对分享会成稿做系统 review，确保成稿忠实实现骨架设计、语言表达准确、流程节奏合理。

## 必读参考

执行前读取：

- `references/review-checklist.md`

## 输入

需要两个文件：

- **成稿**：分享会完整稿（逐字稿 / 执行稿）。
- **方向骨架**：该 case 的分享会方向骨架。

两个文件路径由调用方提供。

## 工作流程

1. 读取成稿和方向骨架。
2. 按 `references/review-checklist.md` 的 5 个维度逐项检查。
3. 输出优先级分级的 review 报告（P0 / P1 / P2）。
4. 等用户确认修改范围。
5. 逐条修改成稿。
6. 交付修改后的最终成稿。

## Review 报告格式

每条 review 发现包含：

- **优先级**：P0（必须修）/ P1（建议修）/ P2（可选修）
- **维度**：结构忠实度 / 语言表达 / 流程设计 / 设计意图 / 完整性
- **位置**：成稿中的具体段落或章节
- **问题描述**：具体说明问题是什么
- **修改建议**：给出具体的修改方向或示例

### 优先级定义

- **P0（必须修）**：影响核心结构、信息真实性或现场可执行性。例如：成稿遗漏骨架的关键设计、引语语言失真、段落间严重重复导致新鲜感断裂。
- **P1（建议修）**：影响现场效果、节奏或家长体验。例如：过渡跳跃、情感密度不均、抽象概念未具体化。
- **P2（可选修）**：锦上添花，不影响整体效果。例如：散场措辞微调、个别措辞优化。

## Review 维度概览

详见 `references/review-checklist.md`。五个维度：

1. **结构忠实度**：成稿是否完整实现骨架的每个字段。
2. **语言表达**：信息重复、引语真实性、抽象概念具体化、禁用词。
3. **流程设计**：段落过渡、情感密度、兜回收尾重复、呼吸点。
4. **设计意图**：骨架关键设计是否充分体现。
5. **完整性**：补采备用方案、可公开性边界、PPT 清单对齐。

## 执行原则

- review 是对照骨架做检查，不是重新设计。不要在 review 阶段改变骨架已确认的方向。
- review 报告只指出问题和建议，不直接修改成稿。等用户确认后再改。
- 如果发现骨架本身有设计问题（而非成稿实现问题），单独标注为"骨架层面发现"，不混入成稿 review 报告。
- 修改成稿时，只改 review 报告中用户确认的条目，不做额外改动。
